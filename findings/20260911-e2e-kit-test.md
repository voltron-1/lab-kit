## 2. Findings

### 2.1 `lab` is broken when invoked through a symlink — MEDIUM — **FIXED (phase 1)**

```
$ ln -s ~/lab-kit/bin/lab ~/.local/bin/lab
$ lab status
/home/you/.local/bin/lab: line 10: /home/you/.local/lib/common.sh: No such file or directory   (exit 1)
```

`bin/lab:6` resolves the repo root without following the symlink:

    LAB_ROOT=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/.." && pwd)

`${BASH_SOURCE[0]}` is the symlink's own path, so `LAB_ROOT` becomes the
symlink's parent. Symlinking a CLI into `~/.local/bin` or `/usr/local/bin` is
the normal way to install one; the README's `export PATH="$PWD/bin:$PATH"`
happens to dodge it. Fix is one line — canonicalize first:

    LAB_ROOT=$(cd -- "$(dirname -- "$(readlink -f -- "${BASH_SOURCE[0]}")")/.." && pwd)

### 2.3 The SOC track's guided steps print the graded answer key — HIGH — **FIXED (phase 3)**

`soc/L4.8` is the Phase 4 gate. Its brief:

    - `q5=tp`, `q5e=cm-0311-0715`, `q5esc=y`  <-- ESCALATION TARGET

`check.sh` asserts exactly those strings. The same holds for `soc/L3.7` (P3
gate, all 8 answers listed), `soc/L7.6` (capstone, all 11), `soc/L5.5` (all 6
phish verdicts), `soc/L6.6` (verdict + cited event ID).

Measured across the kit — graded literals from each `check.sh` versus the text
of its own `lab.md`:

| Track | labs whose brief contains ≥80% of graded values | labs that withhold them |
|---|---|---|
| soc | **27** | 21 |
| ps | 10 (mostly taught type/cmdlet names — low severity) | 6 |
| bash | 0 | 5 |
| rust | 0 | 1 |
| demo | 1 (intentional — it is the tutorial) | — |

split 27/21, so this reads as drift rather than a deliberate contract — and
`docs/kit-contracts.md` only forbids leakage in hints level 1 and keeps quiz
answers base64'd, saying nothing about guided steps. The three phase gates
(L3.7, L4.8) and the capstone (L7.6) are the ones that matter: a gate that
prints its own key cannot gate.

`tests/acceptance.sh` cannot catch this — it fabricates the passing artifacts
itself, so a leaked answer key and a correctly-hidden one look identical to it.

**Decision (2026-09-11): the values come out of the briefs.** Fixed in phase 3:

1. **The questions moved into the answer templates.** Every soc lab that grades
   an `answers.txt` now ships a `files/*answers*template*` whose every line names
   what it wants (`q3=   # logon type meaning "network" (integer)`). Twelve were
   derived straight from the build plans' own `qN= # question -> answer` grammar,
   dropping the answer half; the rest were written by hand. Every graded key has
   a template line — checked mechanically.
2. **29 briefs rewritten.** The "Fill answers.txt: q1=4624, q2=4625, …" block is
   gone; the step now reads "Fill `answers.txt`. Every line in the template names
   exactly what it wants — answer each one from the evidence above." Method steps
   (the `jq` extractions in L4.2, the `sha256sum` in L5.3) were kept verbatim.
   L1.1 kept its eight observation statements and lost only the `→ d` answers.
3. **Two payloads that *were* the answer key were rebuilt as evidence.**
   `L4.7/files/queue.json` and `L4.8/files/queue.json` shipped `"verdict": "tp"`,
   `"cite": …`, `"escalate": "y"` for all 22 alerts. They now carry the facts that
   decide each alert (61 failed logons before the success; a backup inside its
   BKP-NIGHTLY window; a "mimikatz" hit inside the EDR's own signature database;
   a PsExec install under change ticket CHG-4471) and no verdict field.
4. **The four shipped model answers no longer pass their own graders.** `cp
   model-report.md report.md` scored 11/11 on the P5 gate; the same trick scored
   13/13 on L6.6, 15/15 on L7.7 and 11/11 on L6.4. Each model is now a worked
   example of a *different* case (the 2026-03-12 DNS-tunnel case, or a link-based
   phish), so it still shows the shape of a good report but fails the grader's
   technique/verdict assertions when submitted verbatim. Re-tested: 10/11, 10/11,
   12/13, 13/15 — all FAIL.
5. **Eight ps briefs** stopped handing over the literal contents of the graded
   file (`notes.txt`, `classify.txt`, `prediction.txt`). The terms themselves stay

## 6. Phase 5 — the interactive session (2026-09-11)

New: `lab` with no arguments (or `lab session`) runs one fixed flow — select a
track → a checkpoint decision (resume / start from the beginning) → the labs,
driven by `check`, `hint`, `brief`, `skip`, `quit` with no lab ids to type.

- `lib/session.sh` is a driver, not a second grading path: it calls the same
  `cmd_start` / `cmd_check` / `cmd_hint` in a subshell (their `exit` ends the
  command, not the session), so every state write still goes through
  `state_apply`.
- **Start from the beginning moves the pointer only** — no pass, skip mark or
  recap is ever cleared.
- **The frontier still gates.** The session picks the next lab; it never opens
  one past the frontier. `skip` is the only way past an unpassed lab, it
  confirms first, and it marks `⏭` through the same `--force` path.
- With no terminal on stdin, bare `lab` prints usage exactly as before, so
  scripts and CI are unaffected.
- `tests/session.sh` — 44 assertions driving the real menus on a pty via
  `script`, including a bounded timeout so a session that stops consuming input
  fails instead of wedging the run. Documented in README, CONTRIBUTING and
  `docs/kit-contracts.md`.

One bug the tests caught in my own code: a bare `[[ -n "$x" ]] && next="$x"`
would have aborted the whole session under `set -e` at the end of a track.
