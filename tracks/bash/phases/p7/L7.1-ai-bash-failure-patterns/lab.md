## BRIEF
AI models produce dangerous Bash by default:
- **Missing strict mode**: No `set -euo pipefail`, allowing silent error cascade.
- **Unguarded `cd`**: If `cd $SRC_DIR` fails, subsequent relative commands operate on the wrong directory.
- **Dangerous constructs**: `eval $POST_HOOK` offered as "flexible hooks" opens arbitrary code execution (CWE-78).
- **ShellCheck limitation**: ShellCheck catches syntax issues (e.g. `SC2164`, `SC2006`), but is blind to logic flaws and untrusted data execution.

In this lab, you audit `ai-backup.sh`, run ShellCheck, and record the 7 audit answers in `answers.txt`.

## GUIDED STEPS

1. **Inspect `ai-backup.sh` cold**:
   Inspect `ai-backup.sh`:
   ```bash
   #!/bin/bash
   # TEACHING SAMPLE — deliberately flawed. Never run this.
   # Backup script generated by AI assistant
   SRC_DIR=$1
   BACKUP_DIR=/var/backups/logs
   STAMP=`date +%Y%m%d`
   BACKUP_NAME=backup-$STAMP.tar.gz
   cd $SRC_DIR
   find $BACKUP_DIR -name "*.tar.gz" -mtime +30 -exec rm {} \;
   tar -czf $BACKUP_DIR/$BACKUP_NAME .
   if [ -n "$POST_HOOK" ]; then
       eval $POST_HOOK
   fi
   ```

2. **Run ShellCheck to observe static analysis findings**:
   ```bash
   shellcheck -x -S style ai-backup.sh
   ```
   Observe findings:
   - `SC2006`: Use `$(...)` instead of legacy backticks `` `...` ``.
   - `SC2164`: Use `cd ... || exit` in case `cd` fails.
   - `SC2086`: Double quote to prevent globbing and word splitting.

3. **Record your audit findings**:
   Copy `answers.template.txt` to `answers.txt`:
   ```bash
   cp answers.template.txt answers.txt
   ```
   Set:
   - `strictmode=pipefail` (no `set -euo pipefail` preamble)
   - `cdrisk=wrongdir` (failed `cd` causes `tar .` to archive current directory)
   - `execflaw=evalhook` (`eval $POST_HOOK` executes arbitrary code)
   - `sc2164=sc2164` (names unguarded `cd`)
   - `sc2006=sc2006` (names legacy backticks)
   - `blindspot=evalhook` (ShellCheck cannot prove `POST_HOOK` is untrusted)
   - `tell=comments` (cheerful exclamation marks explaining dangerous features)

4. **Verify your work**:
   ```bash
   lab check bash L7.1
   ```
